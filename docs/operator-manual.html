一本の動画は、この順番で作る。

概要ページ（system-overview.html）がシステム「何を作っているか」を説明するページだとすれば、このページは「あなたが何を打ち、どこを確認し、いつ承認するか」の手順書です。各ステップでシステムが自動で行う処理は短く添え、詳しい仕様は折りたたみの中に収めています。

00

このマニュアルの読み方

人間あなたの操作

コマンド入力・画面確認・承認。公開判断と最終責任は常に人間が持ちます。

自動システムの決定論的処理

コードが同じ入力から同じ結果を出す処理。座標計算・検証・組み立て・品質検査など。AIは関与しません。

AIAIの提案生成

編集方針や修正解釈の「案」を作ります。検証を通るまで正式な成果物にならず、承認権限も持ちません。

コマンドはすべて video-pipeline/ ディレクトリで実行します。入口は uv run python -m services.cli ＜操作名＞ に統一されており、登録されていない操作（シェル・ファイル直接操作・ネットワーク・UI）は名前付きで拒否されます。各ステップの緑の箱は「その裏でシステムが自動で行うこと」、折りたたみ（＋）は深掘りしたいときだけ開いてください。

02

手順詳細

各ステップは「目的 → あなたの操作 → 確認ポイント → システムが自動で行うこと」の順で書かれています。コマンド中の <…> は前のステップの出力で置き換わる値です。

0

準備 — 素材と設定を置く

人間 ここだけは自動化されません

撮影素材を1つのEpisodeディレクトリに集め、設定ファイルを書く。これがパイプラインへの唯一の入口です。

やること
  • Episode用ディレクトリ（例: jobs/my-episode/）を作り、撮影素材を配置する
  • Episode設定ファイル（episode.json）に、素材の場所・言語・申告事項（プライバシー/権利フラグ）を記述する（詳細は下の展開を参照）
  • 契約条件（話者1名・ハードカット中心・総素材90分以内 等）に合うEpisodeか確認する
Episode設定ファイル（episode.json）とは
実行が進むとディレクトリ内に自動生成されるもの（素材台帳・座標対応表・解析結果・編集プラン・プレビューMP4・修正履歴）とは別に、あなたが最初に置く設定ファイルは episode.json の1つだけです。Phase 1の取り込みはこのファイルを見つけるところから始まります。中身の例: 
{
  "schema_version": "real-episode-v1",
  "episode_id": "my-episode-001",
  "video_path": "sources/main.mp4",
  "audio_path": null,
  "language": "ja",
  "declared_privacy_flags": [],
  "declared_rights_flags": [],
  "fixture_only": false
}
フィールド意味
schema_version固定値 real-episode-v1。書式の版であり、書き換えません。
episode_idこのEpisodeの識別子。検証用フィクスチャと同名のIDは拒否されます。
video_pathメイン映像ファイル。Episodeディレクトリからの相対パス、または絶対パス。
audio_path現在は必ず null。音声は映像ファイルに含まれている前提で、別ファイルの音声はこの契約では対象外です。
language現在は "ja" のみ。
declared_privacy_flagsあなたが事前に申告するプライバシー問題（顔・ナンバープレート等）。申告すると対応する人間ゲートを通るまで先へ進めません。
declared_rights_flagsあなたが事前に申告する権利問題（BGM権利等）。同上。
fixture_only常に false。検証用素材と実素材を混同させないための固定値です。
契約条件はどこで・どう判定されるか
契約条件はEpisodeごとに設定するものではなく、システム側に固定された「対応対象の定義」です。あなたが設定で「契約を選ぶ」必要はありません。
  • 判定タイミング: STEP 1（取り込み）の実行時。ffprobeによる実測値（総尺・映像/音声ストリームの有無・可変フレームレートかどうか）と、episode.json への申告内容を組み合わせて機械判定します。
  • 主な条件（実装値）: 言語＝日本語／総素材尺＝90分以内（5,400秒）／話者数＝分離可能な少人数まで／単一の主映像＋音声あり。
  • 対象外の扱い: 失敗（エラー停止）ではなく「対象外」と判定され、理由コードが返ります。KPI計測の分母から分離されるだけで、素材自体は残ります。
  • 申告フラグがある場合: プライバシー・権利の申告があると「人間ゲート開放」として停止します。解消するか、人間の明示承認を通すまで先へ進めません。
1

取り込みと解析

自動 phase1 run --stop ANALYZED

素材を機械可読な状態に変換し、音声・画質を解析して「検索できる素材データベース」を作る。

あなたの操作
uv run python -m services.cli phase1 run \ --episode-root jobs/<episode_id> --stop ANALYZED --out <report.json>
システムが自動で行うこと
① 元素材をハッシュ化して不変保存（以後どこでも元素材は変更されない）　② 必要なら固定フレームレートの中間素材を生成し、原本との座標対応表を作成　③ ローカル音声認識（whisper.cpp・クラウド送信なし）で文字起こしと時間情報を抽出　④ 無音・言い淀み・音量異常・場面転換・ブレ等を解析　⑤ 検索用索引を構築
確認ポイント
出力レポートで適格性判定（対象Episodeかどうか）と文字起こしの品質を確認します。ここで文字起こしが大きく崩れていると、後続の編集提案の精度も落ちます。
なぜ「AIに任せない」のか（決定論的処理の理由）
  • 座標変換: フレーム位置の換算は1フレームのずれが映像のズレに直結するため、有理数・整数演算のみで行い、丸め規則も固定します。AIの推論には入れません。
  • 元素材の不変保存: ハッシュ付きで保存し、以後の全工程はこのハッシュを参照します。「どの素材を使ったか」が後から証明できます。
  • 音声認識のローカル実行: 音声はプライバシーに関わるため、既定では外部送信せずローカルのwhisper.cppで処理します。バージョンとモデルはハッシュ固定です。
2

編集プランの確定

AI自動 phase1 run --stop PLAN_COMMITTED

AIが編集方針の「案」を作り、検証を通ったものだけが正式な編集プランとして確定されます。

あなたの操作
uv run python -m services.cli phase1 run \ --episode-root jobs/<episode_id> --stop PLAN_COMMITTED --out <report.json>
システムが自動で行うこと
① AI編集ディレクターが素材を検索・評価し選定プランの案を生成（青＝AIの領域はここまで）　② 形式・意味・ロック・機能対応の4段階検証を通過した案だけ確定　③ 制約プランナー（決定論的コード）が目標尺に合わせて配分を解き、必須収録・順序などの硬い制約を保証　④ 編集プラン確定 → タイムライン中間表現へ変換
確認ポイント
レポートで必須収録（Must Include）が満たされているか、制約を解けなかった場合は実現不可能レポートが出ていないかを確認します。実現不可能の場合は目標尺の変更または設定の見直しが必要です。
「案」と「確定」の分離について
AIの出力は常に提案（Proposal）であり、そのまま採用されません。形式検証（スキーマ通りか）→ 意味検証（存在しない区間を指していないか）→ ロック検証（承認済みの判断と矛盾しないか）→ 機能対応検証（Resolveで実現可能か）の4段階を通過して初めて新しい版として確定（Commit）されます。候補IDや判断IDもAIではなくコードが採番するため、「AIが勝手にIDを作って跡形がなくなる」ことが構造的に起きません。
3

プレビュー生成

自動 phase1 run --stop PREVIEW_READY

編集結果を低解像度のプレビューMP4にして「見える」状態にする。Resolveはまだ起動しません。

あなたの操作
uv run python -m services.cli phase1 run \ --episode-root jobs/<episode_id> --stop PREVIEW_READY --out <report.json>
システムが自動で行うこと
FFmpegにより低解像度プレビューMP4を生成します。ハードカット・基本音声・仮字幕を再現し、どの区間がどの編集判断に対応するかの対応表を添付。重いResolve組み立ての前に編集判断を確定させるのが目的です（不確実性を早く見せる）。
プレビューと最終出力の関係
プレビューは最終画質の証明ではありません。確認するのは編集判断（ショットの採否・発話の削除・構成順序・尺とペース・字幕内容の大きな誤り・BGMの方向性）です。画質やカラーグレードの最終確認はステップ6以降の最終出力で行います。プレビューと最終出力の見た目一致は、別途「見た目一致承認」で保証されます。
4

プレビュー確認と修正指示（ループ）

人間AI 納得いくまで繰り返す

プレビューを普通の動画プレイヤーで見て、気になった点を日本語で伝える。AIがそれを構造化された修正指示に変換し、あなたが確認して適用します。

あなたの操作 — ①指示文を書く

テキストファイルに自然な日本語で書きます（タイムスタンプ付きで）。

# instruction.txt の例3:12〜3:35は削除。5:40は切るのが早いので、一文前から残す。7:20の字幕を「OpenClaw」に修正。
あなたの操作 — ②提案を作らせる
uv run python -m services.cli review propose \ --bundle <bundle.json> --instruction-file instruction.txt \ --translator-policy <translator-policy.json> --production-policy <policy.json> \ --out proposal.json
あなたの操作 — ③提案を確認して適用
uv run python -m services.cli review apply \ --proposal proposal.json --bundle <bundle.json> --out result.json
システムが自動で行うこと
propose: AIが指示を現在の編集プランと照合し、対象を特定して修正指示の案へ変換。要求・モデルのハッシュを記録し、同じ入力からの再生が可能。
apply: 提案を検証し、基準プランの版が一致することを確認してから1件ずつ履歴に確定。編集プラン・中間表現・プレビューを自動で再生成します。
確認ポイント
proposeの出力の分類を見ます。proposalなら適用可能。曖昧な指示（対象が一意に定まらないもの）は自動適用されず確認へ戻ります——これは仕様であり、曖昧命令の自動適用は0件であることをゲート試験で実証済みです。版が古い場合は競合として停止します。
修正履歴（Review Event）に何が残るか
適用ごとに変更前後のフレーム範囲・理由・冪等性キー付きの履歴が追記され、版番号が上がります。この履歴があるため「なぜこのカットはこうなったのか」を後から辿れます。繰り返し現れる修正傾向は将来のプロフィール改善候補（Phase 5）になりますが、自動でプロフィールが変わることはありません（人の承認が必要）。
5

編集承認（H1チェックポイント）

人間 ここを通らないと組み立てへ進めない

プレビューの内容に納得したら、あなた自身の手で編集承認を記録します。AIはこの操作を実行できません。

あなたの操作 — ①対象ハッシュを表示
uv run python -m services.cli checkpoint show \ --bundle <bundle.json> --receipt <display-receipt.json>

画面に対象ハッシュが表示されます。この表示を行った端末（TTY）と同じものを使って次へ進みます。

あなたの操作 — ②承認を記録
uv run python -m services.cli checkpoint record \ --purpose EDITORIAL_APPROVED --decision approve \ --bundle <bundle.json> --display-receipt <display-receipt.json> \ --out <op-record.jsonl>
あなたの操作 — ③承認成果物を組み立て
uv run python -m services.cli checkpoint export \ --bundle <bundle.json> --display-receipt <display-receipt.json> \ --operation-record <op-record.jsonl> --out <checkpoint.json>
システムが自動で行うこと
承認レコードには目的・対象ハッシュ・判断・操作者ID・時刻が記録され、表示されたハッシュと一致しない記録、AIや自動実行からの記録、他目的への流用はすべて拒否されます。プレビュー修正後はハッシュが変わるため、再承認が必要になります。
確認ポイント
表示されたハッシュを目視確認してからrecordを実行すること。練習用に --fixture を付けると「演習用」マーク付きのレコードが作れますが、これは正式な承認として永久に使えません。
なぜ端末（TTY）限定なのか
承認は「人間がその場で対象を確認して責任を取る」行為です。そのため①表示と②記録を同じ対話端末で行うことを機械的に強制し、自動実行プログラムや製品AIからは呼び出せないようになっています。ただしこれは単一利用者ホスト向けの監査記録であり、暗号学的な本人認証・否認防止ではない限界も仕様に明記されています。
6

Resolveでの組み立てと品質検査

自動 編集承認後に実行可能

確定済みの編集プランからDaVinci Resolve上にタイムラインを完全再構築し、レンダーして品質検査まで自動で行います。

あなたの操作

組み立て・レンダーはパイプラインが実行します。完了後、品質検査を実行して結果を確認します。

uv run python -m services.qc.run \ --render <renders/final.mp4> --policy <qc-policy.json> --out <qc-report.json>
システムが自動で行うこと
① 編集プラン → Resolve用パッケージへ変換（機能対応表で実現可能性を事前確認）　② 空のステージングタイムラインへ完全再構築（既存タイムラインを少しずつ直す方式は取りません）　③ アイテム単位の一致検証: 要求した素材・フレーム範囲・トラックが実際に配置されたか全件照合　④ レンダージョブの監視と出力ファイルの検証　⑤ 決定論的品質検査: 黒フレーム・音割れ・音量基準・字幕の文字化け等を全項目チェック
確認ポイント
品質検査レポートの重大な問題（blocking）が0件かを確認します。アイテム一致検証で1件でもずれがあれば組み立ては合格になりません。「成功しました」という報告ではなく、生の出力バイトからの再計算で判定されます。
組み立てに失敗したらどうなるか
一時的な失敗（タイムアウト・接続断）は回数制限付きで自動再試行されます。形式違反・機能未対応・素材不足などの構造的な問題は自動再試行されず停止し、入力修正または人間確認へ回ります。部分完成のタイムラインを修復して使い続けることはせず、常に空からの完全再構築（クリーンビルド）が基本です。
7

最終確認と公開判断

人間 公開の責任は常に人間

最終レンダーと品質検査結果を確認し、最終承認を記録します。公開可否の判断はAIへ移譲されません。

あなたの操作

最終レンダーMP4を通常プレイヤーで再生し、品質検査レポート・要確認候補を確認します。問題なければ：

uv run python -m services.cli checkpoint record \ --purpose FINAL_APPROVED --decision approve \ --work-id <work-id> --git-sha <コミットSHA> --candidate-id <candidate-id> \ --report-dir <reports/> --out <final-record.jsonl>
システムが自動で行うこと
最終承認では6種のレビューレポート（目標制約・コード品質・セキュリティ・手動QA・文脈調査・デバッグ監査）がすべて承認・同一コミット・同一候補IDであることを機械検証します。1つでも拒否があれば型付きエラーで拒まれ、レコードは書かれません。
手作業が必要になったとき（Manual Freeze）
スキーマで表現できない特殊な手作業をResolve上で行った場合は、その状態を「手作業凍結（Manual Freeze）」として保存します。手作業後のプロジェクト書き出し・最終レンダー・変更ログ・凍結理由をひとまとまりの正本として残すため、後から何が起きたかを失わずに済みます。凍結後、自動組み立てがそのジョブを触ることはありません。
03

失敗したとき、何が起きるか

失敗は3種類に分類され、挙動が異なります。全てが自動で直るわけでも、全てが止まるわけでもありません。

自動で再試行

一時的な問題

タイムアウト、Resolveとの接続断など。回数制限付きで自動的に再試行されます。あなたの対処は不要です。

停止して対処が必要

構造的な問題

形式違反・機能未対応・元素材の不足など。自動再試行はしません。入力を修正するか設定を見直してから再実行します。

人間の判断待ち

確認が必要な問題

曖昧な修正指示・プライバシー申告・権利確認など。NEEDS_HUMAN として記録され、人間の判断があるまで先へ進みません。

よくある質問
  • Q. propose の結果が「曖昧」になった — 指示に時刻や対象の特定情報を足して再proposeします。曖昧なまま適用されることはありません。
  • Q. 承認後にプレビューを修正したくなった — applyするとハッシュが変わるため、ステップ5の再承認が必要です（古い承認は自動失効）。
  • Q. コマンドが「unknown-operation」で拒まれた — 登録済み操作以外は実行できません。下の一覧から探してください。
  • Q. 解析結果が気に入らない — 解析は決定論的です。同じ素材・同じバージョンなら同じ結果になります。変えたい場合は素材か設定（パラメータ）を変えます。
