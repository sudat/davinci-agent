01人間とAI

人間の作業は判断に、AIの作業は提案に限定する

評価指標は自動化率ではなく実作業時間（Active Human Time）。人間は創作の方向性と承認を持ち、AIと決定論的コードの分担を厳密に分ける。

人間が担当すること

判断の主体
  • 撮影する。素材の入口は常に人間。
  • チャンネルと動画の方向性を決める。
  • AIの確度が低い（confidenceが低い）候補だけを、必要に応じて選ぶ。
  • 低解像度の編集プレビューMP4（Editorial Preview）で構成を確認し、AIとの自然言語対話で修正要求を入力する。
  • 品質検査エンジン（QC）が抽出した要確認箇所を確認する。
  • 最終的な公開可否を判断する。
原則公開判断・権利判断・プライバシー判断をAIへ移さない。

AIが担当すること

提案のみ
  • 素材検索方針、候補評価、構成の意味判断。選定プラン（Selection Plan）・編集プラン（Edit Plan）・修正案の提案（Proposal）生成。
  • 自然言語の修正指示を構造化された修正指示（Review Command）へ変換する（Review Translator）。
  • 例外原因の仮説生成（組み立て報告（Build Report）の確認、再試行（Retry）可否の判定案）。
  • テロップ・BGMの意味選択。ただし根拠（Evidence）のない映像内容はプランへ書かない。
境界モデル出力は常に提案（Proposal）。形式（Schema）・意味（Semantic）・ロック（Lock）・機能対応（Capability）の各検証を通過したものだけが新しい版として確定（Commit）される。AIにはシェル実行・ファイル書き込み・ネットワークアクセスの権限を渡さない。

AIが所有しない決定

座標・尺計算、制約解決、最終字幕分割、トラック割り当て、組み立て成功判定、再試行実行、品質検査合格、プライバシー/権利の却下、最終/公開承認は、すべて決定論的コードまたは人間が所有する。LLMは意味判断・候補評価・構成・例外原因の仮説生成に限定される。

AIロールとモデル

役割（Role）が契約で、モデル（Model）は交換可能な実装。編集ディレクターAI（Editorial Director、GPT-5.6 Sol）と修正指示変換（Review Translator）は実装済み。視覚評価（Visual Judge）はPhase 4で導入、診断アシスタント（Diagnostic Assistant、GLM-5.2）はロール定義のみ。

Control Plane

Job制御基盤 どのArtifactを入力にどのStageを実行したか、Retryしてよいか、人間確認が必要か、どのVersionが承認済みかを管理する。

ジョブ状態機械Job State Machine

工程の遷移・冪等性（同じ入力なら同じ結果）をCAS（比較して設定）と期限付きリース（Lease＝排他権）で単一書き込み元に保証。

成果物登録簿Artifact Registry

不変のファイル成果物ストアと系譜（lineage）管理。原子的な公開（atomic publish）・クラッシュ復帰・迷子成果物の整合（orphan reconciliation）。

機能対応表Capability Matrix

Resolve機能の実測表。「APIが存在する」と「安全に自動化できる」を区別し、実機検証済み（live_verified）でのみ採用。

確定済み設定Resolved Configuration

システム既定→ジャンル→チャンネル→Episode単位の優先度で解決。ジョブ開始時にスナップショットして固定。

証跡台帳Evidence Ledger

実行前の事前記録（fsync）と前要素ハッシュ連鎖を持つ試行台帳。Gate合否は報告値でなく生バイトから再計算。

ポリシー防護Policy Guard

予算・データポリシー・権限の強制。クラウド送信可否、ローカル限定モード、実装範囲チェック。

承認入口（TTY専用）Approval Ingress

人間承認の唯一の入口。端末（TTY）専用のコマンドライン操作で、製品AI・自動実行プログラムは呼び出せない。

ツールチェーン固定Toolchain Lock

uv、CPython、FFmpeg、whisper.cpp、CMake、Semgrepをバイナリ・モデルハッシュ単位でPhase別に固定。

03ジョブ状態機械

長いAI対話をジョブ指揮者（Orchestrator）にしない、12状態の明示的な状態機械

各工程は明示的な入力・出力・成功条件を持ち、冪等（同じ入力なら同じ結果）に実行される。AIの長い連続操作（tool-call chain）へパイプラインを依存させない。状態名はシステム内の識別子のため英語表記。

6PLAN_COMMITTED
7PREVIEW_READY
8EDITORIAL_APPROVED
9RESOLVE_BUILT

12FROZEN
GATE 編集承認（EDITORIAL_APPROVED）は最終組み立ての必須ゲート。承認なしの PREVIEW_READY から RESOLVE_BUILT への遷移は禁止され、テストで保証されている。プレビューを通さずResolveでの組み立てへ進むと、編集判断の問題とResolve自動化の問題が混ざる。

冪等性キー（Idempotency Key）

同じキーの成功成果物がある場合は再利用する。コード変更後も古いキーで成功を誤再利用しないよう、V4.2で code_snapshot_id を追加。

stage_name + sorted(input_artifact_hashes) + runner_version + code_snapshot_id

状態遷移はCAS（期待状態と親ハッシュの一致確認）で行い、競合した側は SUPERSEDED（無効化）になる。クラッシュ後の復旧は最後に確定された成果物から再開する。

補助状態と再試行の分類

RUNNING＝実行中FAILED_RETRYABLE＝再試行可FAILED_BLOCKING＝要対処NEEDS_HUMAN＝人間確認待ちCANCELLED＝中止SUPERSEDED＝無効化

タイムアウト・一時的なResolve接続断は回数制限付きで自動再試行。形式違反・機能未対応・元素材欠落は自動再試行せず、入力修正または人間確認へ送る。

04正準時間座標

四つの正準時間座標。混ぜない、丸めない、仮定しない

時刻は「Original Timestamp」「Edit Video Position」「Edit Audio Position」「Record Position」の座標で厳密に扱う。変換はConform Layerに集約し、有理数・整数演算のみで行う。

原本

原本時刻Original Timestamp

PTS + time_base

カメラが記録した原本の時間。撮影素材は一切変更せず、この座標のまま保存する。

編集・映像

編集映像位置Edit Video Position

整数フレーム + フレームレート

編集用素材上の映像位置。可変フレームレート（VFR）素材は直接編集せず、固定フレームレート（CFR）の中間素材を生成してから扱う。

編集・音声

編集音声位置Edit Audio Position

整数サンプル + サンプルレート

編集用素材上の音声位置。字幕と文字起こしトークンは原則このサンプル座標に結び付ける。

タイムライン

配置位置Record Position

整数フレーム（タイムライン上）

完成タイムライン上の配置位置。サンプルからタイムラインフレームへの変換はコンパイラが行う。

すべての区間は半開区間

[start, end) で表現し、小数秒（float）を正準保存に使わない。丸め規則を明示し、hypothesis（プロパティテストライブラリ）で単調性・境界保持・決定的丸めを検証済み。

一致を仮定しない

Analyzerの秒・ffprobeのPTS・ResolveのSource Frameが一致すると仮定しない。OriginalとEdit Sourceの対応はConform Map（PTSからframeへのテーブル・sample mapping）としてVersioned Artifactで保存する。

1

プレビューを通常プレイヤーで再生人間

低解像度の編集プレビューMP4で、ショットの採否・発話の削除・構成順序・尺とペース（Pacing）・必須収録（Must Include）の充足・字幕内容の大きな誤り・BGMの方向性を確認する。

2

自然言語で修正指示人間

「3:12〜3:35は削除」「7:20の字幕を修正」のように、タイムスタンプ付きの自然な日本語で伝える。

3

構造化された修正指示へ変換AI

修正指示変換AI（Review Translator）が厳密なJSONスキーマ出力の指示案（Command Proposal）へ変換。要求/モデルハッシュを記録し、同じ入力からの再生（replay）が可能。修正履歴（Review Event）には変更前後・理由・冪等性キーが残る。

4

曖昧な指示だけ確認人間

対象が一意に定まらない指示だけ人間へ確認する。曖昧な命令の自動適用は0件（phase-0cゲートで実証済み）。基準プランの版（Base Plan Version）が不一致なら競合（Conflict）として止める。

5

新しい編集プラン / 中間表現 / プレビューを再生成コード

決定論的な適用器（Reducer）が履歴を順に適用し、新しい編集プラン・タイムライン中間表現・プレビューを再生成。冪等性・イベント順序の非可換性・無関係な判断への不影響をテスト済み。この段階でResolveはまだ動かない。

06承認モデル

承認は目的束縛の操作レコード。AIは承認できない

人間の承認は、端末（TTY）専用コマンドが表示した対象ハッシュを操作者が確認した上で記録される、目的ごとに束縛された操作レコード（Operation Record）として保存される。

入口ローカルTTY専用CLI

checkpoint show / record / export。目的と対象ハッシュの組み合わせごとに独立したレコードになり、他目的のレコード流用、対象ハッシュ不一致、AI・自動実行からの発行はすべて拒否される。レコードには目的（purpose）、対象ハッシュ、判断内容、操作者ID、ローカルuid、時刻、失効させた旧レコードを含む。

分離製品AIは呼び出せない

編集ディレクターAIなどの製品AIと自動実行プログラムはこの経路を呼び出せない。承認の主体は常にローカルホストの操作者のみ。確認のゲートは編集・見た目・最終の独立した記録として運用される。

Editorial
編集承認

EDITORIAL_APPROVED。プレビューでの構成確定。最終組み立ての必須ゲート。

Presentation
見た目一致承認

PRESENTATION_APPROVED。プレビューと最終出力の見た目の一致（parity）。目次・素材（Manifest/Asset）の変更で自動失効。

Privacy
プライバシー確認

重大なプライバシー問題の解消または人間の明示承認。通常の確認予算（Review Budget）外。

Rights
権利確認

BGM・効果音・イントロ等の権利期限・用途外使用・ファイル改変のゲート。

Final
最終承認

最終レンダー・組み立て報告・品質検査結果の不変セット（Bundle）に対する承認。

Publication
公開判断

公開可否の最終判断。AIへ移譲しない人間の専権。

Manual Freeze
手作業凍結

スキーマで表現できない手作業の後、タイムラインを例外的に正本化して自動化を凍結。

限界の明記 本機構は単一利用者ホスト向けの監査チェックポイントであり、暗号学的な本人認証・否認防止（non-repudiation）ではない。未記録の実行、台帳全体の差し替え、ワークスペース所有者/root権限による改ざんは検出できない。この限界を仕様として明記する。
07フェーズとゲート

Phaseは機能数ではなく、不確実性を一つずつ潰す順に並んでいる

F1

計画遵守監査。候補の目録/証跡照合、実行記録の検証、識別情報の再計算。

F2

コード品質レビュー。候補抽出物への固定環境での静的解析・型検査・オフライン試験。

F4

F3

08実装スタック

再現性のために、ツールチェーンごと固定する

「同じツール環境」を検証可能な定義にするため、バイナリ・モデルハッシュまでPhase別に固定（Toolchain Lock）して継承管理する。正本は常にファイル成果物。SQLiteとDuckDBは再生成可能な補助構造に限る。

09意図的に作らないもの

今は作らないもの

先回り実装をしない。Phase 4以降の機能は未実装であることをテストで保証し、必要になったとき（実素材の失敗から）初めて追加する。

PHASE 4旅行・POV支援モード（Travel/POV）

シーン検出、動き解析、視覚類似、視覚評価AI（Visual Judge）、J/Lカット、Bロール。視覚候補ベースの編集も完全自動選択ではなく候補提示型（Candidate-assisted）から始める。

PHASE 5レビュー学習（Review Learning）

過去の編集プラン取得、プロフィール変更提案、効果確認用の保留評価（Holdout）。get_review_examples 等の取得APIは存在しないことをテストで保証している。プロフィール自動更新は常に禁止。

PHASE 5専用レビューUI

「残す/削除/トリム」ボタンやシークUIは作らない。自然言語での確認が複数本運用され、人間時間のボトルネックが実測された場合にだけ追加する。

PHASE 6Shorts等の派生動画

本編パイプラインの安定が先。素材ストアと候補は再利用するが、編集プランは本編と別に作る。

PHASE 4自動プライバシー検出

現状は人間が申告したプライバシー/権利の問題を受け付け、人間のゲートを強制するのみ。自動検出器の読み込み自体が範囲チェックで拒否されることをテストで保証。

非目標トランジション / 可変速度 / マルチカム自動化

トランジション自動追加、可変速度再生（Retime）、ネイティブマルチカム、ショットごとのAIカラーグレード、複雑なFusion合成は対象外。ハードカット・一定速再生に限定する。

未評価

技術フィクスチャ（検証用素材）だけで30分KPIや実編集品質の達成を主張しない。実作業時間（Active Human Time）は実素材Episodeを実運用して初めて評価できる指標であり、合成データの指標を実人間時間と混同しない。あらゆるジャンルへの同時対応、Resolve全機能自動化、分散キュー・第二Resolveホスト等も非目標として明示的に排除済み。
