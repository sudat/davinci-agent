# Episode Cockpit UX再構成指示

## 目的

現在実装済みの機能を、動画制作者が迷わず順番に使える画面へ並べ直す。新機能や新しい仕組みは追加せず、既存機能の表示順、名称、条件表示を変更する。

この文書の「ページ」は利用者から見た作業画面を指す。実装上は既存の `/new-episode`、`/episodes/[id]`、`/references` を維持し、`/episodes/[id]` 内を現在段階に応じて切り替えてよい。ページごとに新しいURLや状態管理を増やす必要はない（KISS・YAGNI）。

## 全画面共通

- 上部には `素材 → 方向 → 試し動画 → 全編確認` の現在位置だけを表示する。
- 通常画面で同時に見せるのは「いま見るもの」「いま入力するもの」「次の主操作」の3つまで。
- 完了した段階は1〜3行の要約へ畳む。過去のカードや内部結果を展開したまま残さない。
- `episode_id`、版番号、hash、stage、flag、AI呼出回数、区間数、処理秒数、構造検証項目は通常画面に出さない。
- 技術情報は画面末尾の `詳しい記録` へまとめる。
- 主ボタンは各画面1つ。副操作は文字ボタンまたは控えめなボタンにする。
- デスクトップは動画と次の操作を同時に見られる2列、狭い画面は動画→操作の1列にする。
- 画面上の「完成」は最終完成だけに使う。試し動画は `試し動画を保存しました`、全編の途中版は `全編の確認用動画` と呼ぶ。

## 1. 新しい動画を作る

### 利用者の目的

素材と希望を渡して、動画づくりを開始する。

### 通常表示

- 撮影素材のフォルダ
- `どんな動画にしたいですか？` の自由記述
- 明示的に選ぶ場合だけ、保存済みの「いつものスタイル」
- 主ボタン `動画づくりを始める`

### 畳むもの

- 目標尺の細かな指定
- 参考動画の追加
- Cloud送信範囲などの高度な設定
- 過去のスタイル版への復帰

### 既存機能との対応

- `IntakeForm`
- `AdvancedSection`
- `ReferenceList`
- channel styleの選択・復帰

## 2. 編集の方向を決める

### 利用者の目的

希望を文章で伝え、AIの提案を選ぶか言い直す。

### 通常表示

- `どんな雰囲気にしたいですか？` の相談欄
- `相談した内容`
- `AIの提案`。基本1案、比較が必要なときだけ最大2案
- 各案の短い説明と `この方向で試す`
- `少し変えたい` の自由記述
- 任意リンク `画像で雰囲気を見る`

### 採用後の要約

`採用した方向` として、構成・見た目・音のうち実際に指定された内容だけを2〜3行で表示する。

### 畳むもの

- AI接続結果
- 構造検査結果
- 未確認字段の列挙
- 予算の詳細数値
- 方針の内部記録

### 既存機能との対応

- `ConsultationPanel`
- `ConsultationEntryList`
- `ConsultationProposalCard`
- `ConsultationJudgmentForm`
- 任意画像生成
- `StyleSaveButton`

## 3. 試し動画を確認する

### 利用者の目的

採用した方向が実際の映像でどうなるかを、複数の代表場面で確認する。

### 通常表示

- 大きな動画プレイヤー
- `採用した方向の見本`
- `3場面・合計18秒` のような平易な内訳
- 場面名または位置の短い表示
- 採用方向の要約2〜3行
- `見てどうでしたか？` の感想欄
- 副操作 `修正してもう一度見る`
- 主操作 `この方向で全編へ進む`

### 必須条件

- 修正前に作られた「先頭30秒だけ」の動画を代表場面の見本として使わない。
- 現行の代表場面選定で新しく作られた動画だけを表示する。
- 撮影素材の切り出しと生成画像を混同しない。動画には `撮影素材から作成`、生成画像には `生成したイメージ` と表示する。
- 試し動画、全編の確認用動画、完成版を同じプレイヤーで曖昧に扱わない。

### 既存機能との対応

- `ConsultationSampleSection`
- sample preview API
- full authorization
- 相談への再入力

## 4. 全編を確認する

### 利用者の目的

全編を見て、気になる位置を直し、本人評価を記録する。

### 通常表示

- `全編の確認用動画`
- 現在の再生位置を自動で付ける修正欄
- 主操作 `この位置を修正する`
- 横版表示と、必要な場合だけ `縦版を作る`
- 手作業または停止がある場合だけ、1行の `確認が必要です` と具体的な次操作
- 最後の3問

### 非表示条件

- `FinishingDomainPanel` は、`manual_fallback_required` または `blocked` が1件もなければ通常画面に描画しない。読み込み中、未実行、適用済み、意図的に不要だけの場合も非表示にする。
- 表示する場合も、対象項目と `何をすればよいか` だけを出す。7分野一覧は `詳しい記録` へ置く。
- review flagは、利用者が対応すべきものがある場合だけ通常表示する。

### 既存機能との対応

- `PreviewPlayer`
- `ReviewChatPanel`
- output selection
- `FinishingDomainPanel`
- `SelfCheckSection`
- `BeforeAfterSummary`

## 5. 参考動画と好み

### 利用者の目的

好きな参考動画と、真似したい点・避けたい点を保存する。

### 通常表示

- 参考動画の追加
- 参考動画のサムネイルと自然言語メモ
- 保存済みの「いつものスタイル」の要約
- 必要なときだけA/B比較
- 主操作 `好みを保存`

### 畳むもの

- source ID
- 保存版番号
- sha256
- domain / polarityなどの内部分類名

### 既存機能との対応

- `ReferencesView`
- `ReferenceAnnotator`
- `PairwisePrompt`
- channel style保存

## 予算表示

- 通常時は表示しない。
- いずれかの上限が近い場合だけ、操作欄の近くへ `この動画で試せる回数が残り少なくなっています` と1行表示する。
- 上限到達時は、できない操作と続けられる操作を1行ずつ説明する。
- AI呼出回数、区間数、処理秒数などの数値は `詳しい記録` 内だけに置く。
- `区間の使用数` という言葉は通常画面で使わない。

## 改修の順序

1. ページ別モック画像を基準に、既存componentの表示順と条件を変更する。
2. 通常画面から不要なcomponentを外し、必要なら既存の `details` へ移す。
3. 新しい代表場面の試し動画を正規の予算内で1本作る。
4. 読み込み完了後のデスクトップと375px幅を実ブラウザで確認する。
5. こちらが画像を確認してから本人確認へ渡す。

## 受入条件

- 初見の利用者が説明なしで、現在の段階と次に押す主ボタンを答えられる。
- 1画面に主ボタンが複数競合しない。
- 試し動画画面に、動画・感想欄・全編へ進む操作が同時に見える。
- 仕上げの空表示や全状態一覧が通常画面に出ない。
- 予算の常時ダッシュボードが通常画面に出ない。
- 375px幅で横にはみ出さない。
- console errorがない。
- 本人へ見せる試し動画が、旧先頭30秒ではなく現行の代表場面選定で作られている。
